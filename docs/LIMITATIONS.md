# 한계 — 검은 얼룩은 왜 생기고, 어디까지가 정상인가

이 문서는 과제의 "한계 설명" 항목(25점)을 위한 것이다. **검은 얼룩을 변명하지 않고,
시차(parallax)와 정렬(alignment)이라는 두 원인으로 나눠 설명한다.**

## 1. 검은 얼룩의 정체

뷰어는 화면을 **가우시안 알갱이**로 채운다. 알갱이는 복원된 점 하나에서 나온다.
따라서 **검은 자리 = 복원된 점이 없는 자리**다. 렌더링 문제가 아니다.

점이 없는 이유는 딱 두 가지다.

```
점이 없다
├── (A) 시차 부족 — 그 자리를 볼 수 있는 사진이 한 장뿐이거나, 한 점에서만 봤다
│      → 깊이를 계산할 수 없다 → 모델이 마스크로 버린다
└── (B) 정렬 실패 — 사진은 있는데 카메라 자세가 틀렸다
       → 표면이 두 겹으로 겹치거나, 엉뚱한 깊이로 튄다 → 빈 틈이 남는다
```

**구분법은 얼룩의 모양이다.**

| 모양 | 원인 | 근거 |
|---|---|---|
| 가장자리가 부드럽고 주변 색이 이어짐 | (A) 시차 부족 | 점이 없을 뿐 좌표는 맞다 |
| 이중 윤곽, 두 겹으로 겹침 | (B) 정렬 실패 | 같은 면이 두 위치에 그려졌다 |
| 얼룩 너머로 배경이 비침 | (A) 시차 부족 | 그 면만 빠지고 뒤쪽 점은 있다 |
| 장면이 활처럼 휘어 보임 | (B) 정렬 실패(전역) | 카메라 궤적 전체가 틀었다 |
| 가장자리가 칼같이 잘림 | 마스크 경계 | `mask_edges=True` 가 자른 자리 |

## 2. 왜 시차가 부족해지는가

깊이는 **두 사진에서 같은 점이 얼마나 옆으로 밀려 보이는지**로 잰다.

```
깊이 z ≈ (基线 b × 초점거리 f) / 시차 d
```

`d` 가 0 에 가까우면 `z` 는 무한대로 발산한다. 즉 **한 자리에서만 본 면은 깊이를
못 잡는다.** 카메라가 움직였더라도 그 면이 늘 정면에 있으면 시차가 0 이다.

이 장면에서 그런 자리는 다음과 같다.

| 자리 | 왜 시차가 0 에 가까운가 |
|---|---|
| **시계 유리(크리스탈)** | 투명·반사. 뒤의 문자판과 유리면이 같은 화소에 겹쳐 깊이가 두 값으로 튄다. 모델은 이럴 때 마스크로 버린다 |
| **금속 브레이슬릿의 반사면** | 거울처럼 시점마다 다른 것을 비춘다. 같은 점의 색이 사진마다 달라 정합이 안 된다 |
| **케이스 옆면(베젤)** | 영상에서 거의 정면으로만 보였다. 옆으로 돌아간 프레임이 적다 |
| **손목시계 아래(매트에 닿은 면)** | 물리적으로 가려져 어떤 사진에도 안 나온다 |
| **프레임 밖으로 나간 구간** | 영상 12~16초에 피사체가 화면 아래로 벗어난다. 그 사이 정보가 없다 |

### 2.1 뷰어에서 실제로 확인한 것

문서에 적어 둔 추측을 화면으로 확인했다. 카메라를 고정하고 방위각만 돌려 가며
같은 장면을 찍었다.

| 방위각 | 보이는 것 | 판정 |
|---|---|---|
| 0° (앞) | 시계·매트·나무 책상·키보드가 모두 보인다 | 정상 |
| 90° | 시계가 얇아지고 브레이슬릿이 점 사슬로 풀린다 | (A) 옆면 프레임 부족 |
| **135°** | **매트 조각과 나무 판만 남고 시계는 사라진다** | (A) 뒤쪽 프레임 0장 |
| 고도 −25° (아래) | 매트 밑면은 회색 판, 시계 밑면은 검은 구멍 | (A) 가려진 면 |
| 고도 +80° (위) | 매트·책상은 멀쩡, 시계는 윗면만 | 위에서만 봤다 |

`shots/coverage.jpg` 가 135° 비교다. **앞에서는 보이던 시계가 반대편에서 통째로
사라진다.** 이것이 "퍼짐 비율 1.088 인데 왜 구멍이 있나"에 대한 답이다. 카메라는
충분히 움직였지만 **한쪽 방향으로만** 움직였다.

## 3. 왜 정렬이 실패하는가

정렬은 사진 N장의 카메라 자세를 동시에 푸는 문제다. 아래 경우에 국소 최적해로 빠진다.

| 원인 | 이 장면에서 | 결과 |
|---|---|---|
| 반복 무늬 | 매트의 격자무늬가 규칙적이다 | 격자 한 칸씩 어긋나게 정렬될 수 있다 |
| 빠른 이동 | 12~16초 구간이 빠르게 지나가며 번졌다 | 번진 장은 특징점이 뭉개져 오차가 커진다 |
| 얕은 심도 | 배경이 흐리다 | 배경 특징점이 적어 자세 추정이 피사체에만 의존한다 |
| 반사면 | 금속이 시점마다 다른 색 | 같은 점으로 매칭되지 않는다 |

정렬이 틀리면 증상이 **국소**로 나타난다. 한 부분만 두 겹으로 겹치고 나머지는 멀쩡하다.
전역적으로 틀리면 장면 전체가 활처럼 휜다(제자리 회전 촬영의 전형).

## 4. 해상도에서 오는 한계

모델은 사진을 **518×294** 로 줄여서 받는다. 원본이 1920×1080 이어도 그렇다.
비율에 맞는 칸을 고정된 표에서 고르기 때문이고, 마음대로 올릴 수 없다.

1920 → 518 은 **3.7배 축소**다. 3.7 화소 폭이던 것이 1 화소가 된다.

| 대상 | 축소 후 | 결과 |
|---|---|---|
| 시계 유리 테두리 | 1~2화소 | 계단처럼 각진다 |
| 브레이슬릿 마디 사이 | 1화소 이하 | 이어진 덩어리로 뭉갠다 |
| 매트 격자선 | 2~3화소 | 살아남는다(정렬에 도움) |

**얇은 것이 뭉개지는 것은 모델의 한계가 아니라 입력 해상도의 한계다.**
더 또렷하게 하려면 장수를 늘리는 것이 아니라 **그 앞에서 더 가까이, 더 많이** 찍어야 한다.

## 5. 알갱이 크기에서 오는 한계

`r = K × (장면의 가장 긴 변) / sqrt(N)` 로 반지름을 하나로 정한다.
장면 전체에 같은 크기를 쓰므로 **가까운 곳과 먼 곳의 요구가 다르다.**

- `K` 가 작으면 → 표면에 구멍이 숭숭 뚫린다 (점 사이를 못 메움)
- `K` 가 크면 → 윤곽이 뭉개지고, 얇은 것이 사라진다

이 프로젝트는 `K = 1.4` 하나로 끝냈다. 화면에서 점 사이가 벌어져 보이면 `K` 를 올리고,
윤곽이 뭉개지면 내리면 된다. **바꿀 때는 `measurements.json` 의 `radius` 도 같이
갱신해야 한다** — README 의 68바이트 계산은 `K` 와 무관하지만, 반지름은 장면 크기와
알갱이 수에 따라 달라진다.

**알갱이는 부딪히지 않는다.** 그리기 위한 것이라 딛고 설 면이 없다. 물체를 올려
놓으려면 메시가 따로 필요하다(노트북 부록).

**회전은 쓰지 않았다.** 사원수를 모두 `(w=1, x=y=z=0)` 으로 두었으므로 알갱이는
전부 구(球)다. 방향을 살리려면 학습된 회전을 넘겨야 하는데, 점만 복원한 경우에는
회전 정보가 없다. `.sog` 안의 `quats.webp` 가 198바이트인 이유가 이것이다.

## 6. 압축에서 오는 손실

`.sog` 는 알갱이를 4.99바이트까지 줄인다. 위치·회전·크기·색을 양자화하고, 색은
SH 0차만 남긴다.

- **각도별 색은 원래 없다.** 학습을 걸지 않았으므로 45칸이 비어 있다. 이건 압축
  손실이 아니라 설계상의 선택이다. 결과적으로 **시점을 돌려도 반사가 변하지 않는다**
- 영상 후반(19~23초)에 유리에 비친 보랏빛 반사가 **한 값으로 굳어** 있다. 반사가
  없던 방향에서도 보랏빛이 남는 이유다. 이것도 압축 손실이 아니라 학습 설계의 결과다
- 금속의 반짝임이 사진과 다르게 보이는 이유가 여기 있다
- 양자화로 위치가 조금씩 움직인다. 장면이 작을수록 상대 오차가 커진다

**압축이 점을 지우지는 않는다.** `.sog` 의 알갱이 수는 `.ply` 와 같은 3,496,815개다.
위치를 8비트로 줄이면 점이 조금 옮겨 갈 뿐 없어지지 않는다. 그래서 검은 구멍은
압축 전부터 있던 복원 손실이다.

## 7. 뷰어에서 직접 확인하는 방법

```
1. 열린 화면에서 손가락으로 한 바퀴 돌린다
2. 검게 남는 자리를 찾는다
3. 그 자리가 위 표의 어느 줄인지 고른다
4. README 의 '한계' 절과 대조한다
```

가장 빠른 확인은 **135° 돌려 보는 것**이다. 시계가 사라지면 그 면을 본 프레임이
없다는 뜻이고, 그것이 이 장면의 한계를 한 문장으로 말해 준다.

`?f=scene.ply` 를 붙이면 **압축 전 파일**로 같은 장면을 볼 수 있다(파일이 있을 때).
`.sog` 와 `.ply` 에서 얼룩 위치가 같으면 압축 손실이 아니라 복원 손실이다.
이 비교가 원인을 가르는 가장 빠른 방법이다.

## 8. 정리 — 이 프로젝트가 인정하는 한계

1. **얇은 것과 반사면은 복원되지 않는다.** 시차가 0 이거나 색이 시점마다 달라서다
2. **안 찍힌 면은 영원히 없다.** 각도를 돌리면 검은 자리가 보이는 것이 정상이다
3. **시점별 반사는 재현되지 않는다.** 학습을 걸지 않았으므로
4. **해상도는 518×294 가 상한이다.** 원본을 키워도 안 늘어난다
5. **정렬 오차는 국소적으로 남는다.** 매트 격자 같은 반복 무늬에서 특히

이 다섯 가지를 숨기지 않고 화면에 그대로 드러내는 것이 이 뷰어의 설계다.
