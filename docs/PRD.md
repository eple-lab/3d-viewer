| 항목 | 값 |
|---|---|
| 문서 버전 | 1.0 |
| 작성일 | 2026-11-13 |
| 저장소 | https://github.com/eple-lab/3d-viewer |

## 1. 이 문서의 목적

"영상 하나로 3차원 장면을 만들어 웹 주소로 공유한다"는 과제를 **무엇을 만들고,
무엇을 재고, 어디까지 안 할지** 정한다. 결과물의 합격 여부를 사람이 감으로 판단하지
않도록, 평가 기준 네 가지를 각각 **측정 가능한 수용 기준**으로 바꿔 둔다.

## 2. 배경과 문제

폰으로 방이나 공간을 찍으면 영상은 남지만, 그 안을 다시 걸어 볼 수는 없다.
3D 스캔 앱은 대개 앱 안에서만 열리고, 결과 파일은 수백 MB 라 공유가 안 된다.

이 프로젝트가 푸는 문제는 세 가지다.

1. **복원** — 평범한 폰 영상에서 카메라 자세와 깊이를 동시에 얻는다
2. **경량화** — 그 결과를 웹이 3초 안에 열 수 있는 크기로 줄인다
3. **설명** — 복원이 실패한 자리를 숨기지 않고, 왜 실패했는지 밝힌다

세 번째가 이 과제의 절반이다. 잘 나온 곳만 보여 주면 "예쁜 데모"지 "측정"이 아니다.

## 3. 목표

| 번호 | 목표 | 측정 |
|---|---|---|
| G1 | 폰에서 링크가 열리고 장면이 보인다 | 아이폰/안드로이드 각 1대에서 첫 알갱이까지 5초 이내 |
| G2 | 결과 파일이 깃허브 한도를 넘지 않는다 | `.sog` < 100MiB, 목표 < 20MB |
| G3 | 결과를 숫자로 비교할 수 있다 | README 에 4종 수치(퍼짐·형식별 크기·알갱이 수·알갱이당 바이트) 기재 |
| G4 | 복원 안 된 자리를 설명한다 | 검은 얼룩 위치 3곳 이상 + 원인을 시차·정렬로 서술 |
| G5 | 제3자에게 보내도 문제가 없다 | 공개 판단 근거 1줄 + 얼굴·번호판·개인정보 없음 확인 |

**비목표(명시적으로 안 함)**: 실시간 협업, 편집 기능, 로그인, 서버 저장, 물리 시뮬레이션
(부록으로만 코드 제공).

## 4. 사용자와 시나리오

**주 사용자**: 링크를 받은 사람. 앱 설치 없음, 폰 브라우저, 회선 상태 불명.

```
1. 메신저에서 링크를 받는다
2. 탭한다            → 3초: 로딩 화면, 진행 막대
3. 5초             → 알갱이가 보인다
4. 손가락으로 끈다    → 시점이 바뀐다
5. 고개를 갸웃한다    → 검은 자리가 보인다 (정상, README 에 설명 있음)
```

**보조 사용자**: 이 저장소를 다시 돌려 보는 사람. 코랩에서 노트북을 위에서 아래로
실행하면 같은 결과가 나와야 한다. 단, GPU 배정과 모델 버전에 따라 값은 조금 달라진다.

## 5. 범위

### 포함

- 영상 1편 → 사진 24장 → 점 → 알갱이 → `.sog`
- 정적 웹 뷰어 (three.js + Spark), GitHub Pages 배포
- 수치 측정과 기록 (`measurements.json` → README)
- 실패 지점 문서화

### 제외

- 여러 영상 합치기, 실내 전체 도면화
- 서버·데이터베이스·인증
- 모델 학습(fine-tuning). 각도별 색 45칸은 비워 둔다
- 물리 충돌 (부록 코드로만 제공, 결과물에 미포함)

## 6. 기능 요구

| ID | 요구 | 수용 기준 |
|---|---|---|
| FR-1 | 영상 조건을 자동 판정한다 | 가로/길이/프레임 수를 읽어 통과·실패를 출력 |
| FR-2 | 길이와 무관하게 24장을 뽑는다 | `fps = 24/길이`, 결과 24±1장 |
| FR-3 | 흐린 장을 수치로 표시한다 | 장별 선명도 + 중앙값 + 번진 장 목록 |
| FR-4 | T4 에서 24장 복원이 끝난다 | 60초 이내, GPU 메모리 8GB 이하 |
| FR-5 | 카메라 이동량을 잰다 | `퍼짐/대각선` 비율 출력, 0.1 미만이면 경고 |
| FR-6 | 17칸 알갱이 ply 를 만든다 | 알갱이당 정확히 68바이트, `f_rest` 없음 |
| FR-7 | 웹용으로 줄인다 | `.sog` 생성, 100MiB 미만 |
| FR-8 | 형식별 크기를 비교한다 | ply/splat/compressed.ply/sog 4종 바이트 |
| FR-9 | 브라우저가 파일을 연다 | 알갱이 수 > 0, 카메라 자동 맞춤 |
| FR-10 | 실패를 화면에 설명한다 | 5가지 증상별 안내 문구, 콘솔 오류 노출 |
| FR-11 | 측정값을 한 파일로 남긴다 | `measurements.json` + README 붙여넣기용 표 |

## 8. 평가 기준 → 설계 대응

배점 100점. 각 항목이 **어느 산출물에서 충족되는지** 미리 묶어 둔다.

| 기준 | 배점 | 충족시키는 산출물 | 확인 방법 |
|---|---|---|---|
| 공개 판단 | 25 | `README.md` 공개 판단 절, `docs/PUBLISHING.md` | README 한 줄 + 촬영 대상에 사람·차량·개인물건 없음 |
| 주소 동작 | 25 | `index.html`, `scene.sog`, `.nojekyll`, Pages | 폰에서 열기 + `/scene.sog` 직접 내려받기 |
| 수치 판정 | 25 | `docs/MEASUREMENTS.md`, `measurements.json` | 4종 수치 표 |
| 한계 설명 | 25 | `docs/LIMITATIONS.md`, 뷰어 도움말 | 검은 얼룩 위치 + 시차·정렬 연결 |

**설계 원칙**: 네 항목이 서로 다른 파일에 흩어지지 않게, README 하나만 읽어도
네 가지가 다 보이게 한다. 세부 근거는 `docs/` 로 링크한다.

## 12. 측정 정의

문서마다 값이 달라지지 않도록 수식을 못 박는다.

```
카메라 퍼짐   = ‖max(카메라 위치) − min(카메라 위치)‖
장면 대각선   = ‖max(점) − min(점)‖
퍼짐 비율     = 카메라 퍼짐 / 장면 대각선          (0.1 초과가 정상)

알갱이당 바이트 = (파일 바이트 − 헤더 바이트) / 알갱이 수   (17칸 × 4 = 68)
형식 배수      = .ply 바이트 / 해당 형식 바이트
MB            = 바이트 / 1,000,000   ← 1,048,576 과 구분해 명시
```
