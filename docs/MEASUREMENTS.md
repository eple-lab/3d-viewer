# 측정값 — 무엇을 어떻게 쟀는가

이 문서는 과제의 "수치 판정" 항목(25점)을 위한 것이다. 네 가지 수치를 **정의 →
측정 → 해석** 순서로 적는다. 모든 값은 `data/measurements.json` 에도 그대로 들어 있다.

## 1. 정의

문서마다 숫자가 달라지지 않도록 수식을 먼저 못 박는다.

```
카메라 퍼짐   = ‖max(카메라 위치) − min(카메라 위치)‖        (3차원 유클리드 거리)
장면 대각선   = ‖max(점) − min(점)‖
퍼짐 비율     = 카메라 퍼짐 / 장면 대각선                      ← 0.1 초과가 정상

알갱이당 바이트 = (파일 바이트 − 헤더 바이트) / 알갱이 수       ← 68 이 정상
형식 배수      = .ply 바이트 / 해당 형식 바이트
MB            = 바이트 / 1,000,000   (MiB 는 / 1,048,576)
```

**퍼짐 비율**은 "카메라가 장면 크기에 비해 얼마나 움직였는가"다. 삼각측량의 밑변
길이를 장면 크기로 나눈 셈이라, 장면 크기와 무관하게 비교할 수 있다.
**0.1 미만이면 제자리에서 돌기만 한 것**이고, 결과가 아치형으로 휘어 나온다.

**알갱이당 바이트**는 파일이 규격대로 만들어졌는지 보는 값이다. 17칸 × 4바이트 = 68.
다르면 헤더에 각도별 색(`f_rest`) 45칸이 섞였거나(→ 248), 칸이 빠진 것이다.

## 2. 실측

T4 · 24장 · `facebook/map-anything-apache` · fp16 에서 나온 값입니다. 원본은
`data/measurements.json` 에 있습니다.

### 2.4 `.sog` 안을 열어 본 값

| 항목 | 값 |
|---|---|
| 형식 | SOG v2 (zip) · `splat-transform v3.10.3` |
| 알갱이 수 (`meta.json`) | 3,496,815 — `.ply` 와 동일 |
| 압축 후 알갱이당 | 4.99 B (원본의 7.3%) |
| 텍스처 | `means_l.webp` 10.43MB · `sh0.webp` 5.16MB · `means_u.webp` 1.86MB |
| 회전·크기 | `quats.webp` 198B · `scales.webp` 194B |

**회전·크기 텍스처가 200바이트도 안 되는 이유**는 알갱이마다 값이 같기 때문입니다.
크기는 3,496,815개 모두 0.00181 로 고정했고, 회전도 단위 사원수 하나로 통일했습니다.
균일한 알갱이는 압축률이 가장 좋지만, 표면의 방향을 살릴 수는 없습니다.

## 3. 읽는 법

### 카메라 퍼짐 / 장면 대각선

| 값 | 뜻 | 다음 행동 |
|---|---|---|
| < 0.05 | 제자리 회전에 가깝다 | 재촬영 |
| 0.05 ~ 0.10 | 시차가 부족하다 | 아치형 왜곡을 각오하거나 재촬영 |
| **0.10 ~ 0.50** | 정상. 삼각측량이 된다 | 그대로 진행 |
| > 1.0 | 장면보다 카메라가 더 움직였다 | 대개 작은 물체를 크게 돈 경우. 문제 없음 |

### 알갱이 수

점이 많다고 좋은 것이 아니다. **같은 파일 크기에서 표면을 얼마나 고르게 덮는가**가
중요하다. 점이 지나치게 많으면 `.sog` 가 100MiB 를 넘고, 적으면 구멍이 생긴다.

| 장수 | 예상 점 수 |
|---|---|
| 24 | 200만 ~ 400만 |
| 48 | 400만 ~ 800만 |

### 알갱이당 바이트

| 값 | 뜻 |
|---|---|
| **68** | 정상 (17칸) |
| 248 | `f_rest` 45칸이 들어갔다 → 파일이 3.6배 |
| 32 | `.splat` 형식 (알갱이당 32B 로 재배열) |

### 형식별 크기

배수는 장면과 알갱이 수에 따라 달라진다. **남의 표를 옮기지 말고 이 파일의 값을 쓴다.**
같은 파일인데 도구마다 MB 가 다르게 찍히므로, 표에는 바이트를 함께 적는다.

## 4. 재는 명령

```powershell
# sog 안의 알갱이 수와 바이트 (내려받은 파일이 진짜인지)
uv run --with pillow python scripts\inspect_sog.py scene.sog

# 배포된 파일이 실제로 내려오는지
curl.exe -sI https://eple-lab.github.io/3d-viewer/scene.sog | Select-String "HTTP/|content-length"
```

뷰어 화면 왼쪽 아래에도 **알갱이 수·파일 크기·알갱이당 바이트·장면 지름·fps** 가
표시된다. 문서의 숫자와 브라우저의 숫자가 다르면 문서가 틀린 것이다.

## 5. 브라우저에서 잰 값

| 항목 | 값 | 비고 |
|---|---|---|
| 알갱이 수 | 화면 표시 | Spark 가 푼 개수 |
| 알갱이당 바이트 | 화면 표시 | 내려받은 바이트 / 알갱이 수 |
| 장면 지름 | 화면 표시 | `getBoundingBox` 로 잰 반지름 × 2 |
| 화면 갱신 | 화면 표시 | 기기 성능의 지표 |

파일 크기는 `fetch` 로 받은 `byteLength` 를 쓴다. 서버가 준 `Content-Length` 와
다를 수 있는데(압축 전송 등), **뷰어가 실제로 메모리에 올린 바이트**가 더 정확하다.
